## 宿題

- 取り組んだレベル：基礎

- やったこと：

  MCPサーバーの接続方式をstdioからStreamable HTTPに変更し、同じ質問を実行して比較した。HTTP方式では `uv run python -m app.mcp_server --http` でサーバーを起動し、`app/mcp_servers.json` の設定を `http://127.0.0.1:8000/mcp` に変更した。

  また、`app/tools.py` の `search_glossary` のdocstringを変更し、「宿題の3レベル」に関する質問では必ず用語集を検索するよう明示した。変更前後でツール一覧と実行結果を比較した。

- 結果：

  stdio方式とStreamable HTTP方式の両方で、`glossary_search_glossary` が1回呼び出され、正しい回答が得られた。

  接続方式を比較すると、stdio方式ではエージェントがMCPサーバーを子プロセスとして自動起動し、標準入出力で通信する。一方、HTTP方式ではサーバーを別プロセスとして起動し、ポート8000を使用してHTTP通信する。

  同じモデル（`gemini-3.1-flash-lite`）、同じ質問、同じdocstringで比較した結果は以下のとおりだった。

  | 項目 | stdio方式 | HTTP方式 |
  |---|---|---|
  | ツール呼び出し回数 | 1回 | 1回 |
  | APIリクエスト回数 | 2回 | 2回 |
  | 入力トークン | 817 | 817 |
  | 出力トークン | 164 | 167 |
  | 推定APIコスト | $0.00045025 | $0.00045475 |

  docstring変更前後の比較では、`--list-tools` に表示される説明文が変更された。一方、ツール名と引数は変わらなかった。変更前後とも同じツールが1回呼び出され、回答の主要な内容にも違いはなかった。

- 気づき・疑問：

  MCPを利用すると、ツールの実装を変えずに接続方式を切り替えられることが分かった。また、docstringがモデルに渡されるツールの説明文として使われるため、適切な説明を書くことが重要だと理解した。

  今回はdocstringを変更してもツールの選択は変わらなかった。説明文の違いがツール選択に与える影響を明確にするには、複数の質問や繰り返し実行による検証が必要だと感じた。
